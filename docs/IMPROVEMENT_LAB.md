# 从真实错误到程序改进：跟着结果体验一遍

这段练习带你完成一次实际的改进过程：**运行旧版 → 对照参考发现差异 → 找出原因 → 理解改动 → 运行改进版 → 比较效果**。你只需要依次运行四条命令、打开指定文件并跟着说明阅读，**不需要填写或提交表格，也不需要提交报告**。

本练习使用课程原有的 50 篇摘要和真实模型响应。旧版负责重现原来的预测；改进版在相同预测上运行新的本地程序规则。两版都不产生新的 API 调用，不需要密钥、独立显卡或额外付费。

这一轮保留原来的实体名称、类别和位置，处理的是**标准 ID 链接，以及少数有明确局部证据的关系标签**。它没有重新训练模型，也没有让语言模型重新抽取一遍。这里的目标是理解改进如何发生；本项目仍属于教学方法适配，不是原论文整套实验或指标的严格复现，具体边界见 [METHODS.md](METHODS.md)。

## 开始前：认清三份不同的内容

如果还没有安装，先完成 [操作手册第 1 节](MANUAL.md#1-准备与安装)，激活虚拟环境。以下命令都在包含 `pyproject.toml` 的仓库根目录执行，Windows、macOS 和 Linux 使用相同的命令。

先分清后面会反复出现的三个名称：

- **旧版预测**：程序从真实模型响应及原有规则得到的结果。它可能出错，仍须完整保留，才能与新版公平比较。
- **原数据集参考（gold）**：BioRED 作者提供的人工标注。程序按固定规则与它比较，得到成绩；它也可能有歧义或疑点。
- **本次审阅意见**：阅读原文后对某个字段作出的判断。例如只确认关系标签，并不同时确认两端的物种与 ID。意见中的“保留”“建议修改”和“待审”需要结合其依据理解。

本次汇总覆盖优先表中的 **22／24 条记录**；第 11、12 条尚无填写完成的人工结论，仍保留待审。此前八条中的统一 ID 整理依据原 BioRED 参考，不能把这项整理称作八条都完成了独立专家审核。后面的诊断文件会保留这些区别。

运行产生的文件都位于 `runs/feedback`。查看文件时可在 VS Code 左侧展开此目录；Markdown 文件可以打开预览，JSON／JSONL 文件可以直接搜索文献编号。若要从头另做一遍，四条命令统一换成一个新的工作目录，例如 `runs/feedback-second`，不要混用两次运行的文件。

## 第一步：运行旧版，保留比较的起点

**为什么做：** 在解释某条错误之前，先确认它是旧程序实际生成的结果。后面只看修正后的答案，无法知道程序究竟改进了什么。

**输入：** 50 篇原文、原候选词典、课程保存的真实模型响应。

```bash
python -m bio_knowledge_lab feedback-lab --step baseline --workdir runs/feedback
```

这一步离线重放全部 50 篇，产生：

- `runs/feedback/baseline.jsonl`：旧版预测，包括原文、实体、链接和关系。
- `runs/feedback/baseline_evaluation.json`：旧版与固定 BioRED 参考比较的成绩。

打开 `baseline.jsonl`，搜索文献编号 `18593936`，再找 `survivin`。注意两件事：`text` 是原文中的名称，`links` 中的 `id` 是程序选定的标准身份。旧版把这里的 survivin 链接到小鼠 Birc5 `11799`。**名称被找到了，不代表身份就选对了。**

然后打开 `baseline_evaluation.json`。先认识三个字段，不需要抄写数值：

| 字段 | 它在检查什么 |
|---|---|
| `ner_strict` | 实体的原文位置和类别是否正确 |
| `linking_strict` | 实体识别正确的同时，完整标准 ID 集合是否一致 |
| `relation_end_to_end` | 两端实体身份和关系标签是否共同匹配参考 |

`precision` 看给出的预测有多少匹配，`recall` 看参考中有多少被找到，`f1` 综合两者。F1 不等于简单正确率。链接错误会继续影响关系评价，因此三个分数可能相差很大。

**到这里应明白：** 旧版产物是一份可追溯的预测，评价只是比较，不会把参考答案填回预测。

## 第二步：看差异，追问错在了哪一步

**为什么做：** “与参考不同”只说明需要检查，尚不能说明是模型错、规则错，还是参考存在疑点。把所有差异统称为“抽取错了”，就找不到应该修改的地方。

**输入：** 第一步的旧版预测、固定原参考及本次整理的审阅记录。这些参考用于展示与诊断，不作为改进算法的答案输入。

```bash
python -m bio_knowledge_lab feedback-lab --step inspect --workdir runs/feedback
```

打开 `runs/feedback/inspection.md`。程序已把优先表的 24 条记录排好，展示原文、旧预测、原参考、收到的意见及待审说明。**这份文件由程序生成，你不用填写。** 原记录编号不包含表头；定位时同时认文献编号和 `m`／`r` 编号，避免混淆。

先跟着下面几个例子阅读，不必一次看懂全部 24 条。

### 2.1 survivin：正确对象没有进入候选库

找到 `18593936` 的 `m13`、`m19`、`m39`。本次审阅指出相关实验使用人源膀胱癌细胞，异种移植实验中的小鼠是宿主，不能据此把细胞中的 survivin 都认成小鼠基因。人 BIRC5 对应 `332`，旧版选择了小鼠 `11799`。

问题不仅是“最后选错了”。旧候选库没有收进人 BIRC5；旧词典规则只命中一个小鼠候选，就把它标记为已解决，后续上下文模型直接跳过。**候选里没有正确对象，后面的选择再复杂也无法选对。**

对应的改进思路是从独立数据库完善名称和别名检索，并重新检查匹配的物种依据。不能在程序中写一条“遇到这篇论文就输出 332”的答案表。[原文](https://pubmed.ncbi.nlm.nih.gov/18593936/)与 [NCBI BIRC5](https://www.ncbi.nlm.nih.gov/gene/332)可用于追查依据。

### 2.2 GSK-3beta：一个写法差异怎样传播成两条错误

找到 `19672862` 的 `m26`、`m27`。两条分别是全称和缩写，来自同一句话。旧词典对连字符、空格等别名写法处理不足，先把缩写选成小鼠 Gsk3b `56637`，再将这个身份传播给全称。

这里应该同时检查**别名是否覆盖**和**本次实验的物种背景**。改进名称匹配，不意味着只要去掉空格、符号就能确认身份；仍要结合 Ishikawa 细胞的来源。两个提及可以连接同一个对象，但一次错误选择也会随缩写传播。[原文](https://pubmed.ncbi.nlm.nih.gov/19672862/)、[Ishikawa 细胞记录](https://www.cellosaurus.org/CVCL_2529)、[人 GSK3B](https://www.ncbi.nlm.nih.gov/gene/2932)。

### 2.3 insulin：相同名称不保证每次都是同一个对象

找到 `19463742` 中几次出现的 `insulin`。它们分别位于标题、大鼠实验、细胞实验和总结句中。旧程序按“类型＋名称”合并这些提及，再把一次选择的人的 `3630` 填给组内所有位置。

改进时要回到每一次提及的位置，区分局部实验、标题和总结。原参考对部分提及保留多个物种 ID，这与把它们随意拆成多个新的原文提及不同：原来的一次出现仍应保留原编号和位置。

还要注意：**实验细胞属于某个物种，不足以证明外加胰岛素试剂也来自该物种。** 本轮没有足够依据自动改好这些 insulin 身份，旧 ID 可能仍保留在 `links`，同时 `improvement_review.status` 标记 `needs_review`、`link_review_status` 标记 `pending`，说明“保留待核查候选”，不是“已经确认正确”。`link_status` 即使仍为 `resolved`，也只表示旧算法给出了候选身份，不代表本轮确认了它。不能为了让这些行全部匹配参考而强行填入某个 ID。[原摘要](https://pubmed.ncbi.nlm.nih.gov/19463742/)。

### 2.4 PKCalpha 与 p21／p27：先理解干预，再判断关系

找到 `19672862/r14`、`r15`。原文的关键是“PKCalpha knockdown increased”：敲低 PKCalpha 后，p21 和 p27 水平上升。这里减少的是 PKCalpha，增加的是 p21／p27，支持负向调节。不能看到 `increased` 就直接标为 `Positive_Correlation`。

这两条旧版正向标签与原参考的 `Negative_Correlation` 不符，也与本次字段级审阅意见不符。新版对能够明确识别干预对象和响应对象的局部句式进行保守处理。**改对关系标签，不会自动改对两端的标准 ID。**[原摘要](https://pubmed.ncbi.nlm.nih.gov/19672862/)。

### 2.5 三种差异不应直接改成“正确答案”

继续看以下记录，理解为什么新版不会机械照抄每条审阅建议：

- **VIP—EAE，`25305591/r7`：** 审阅意见把“VIP 缺失后 EAE 减轻”解释成 VIP 与疾病负相关，推理方向有问题；原文还区分外源给药、不同神经肽和受体。原 BioRED 参考为 `Association`。这条适合学习核对审阅意见本身，不宜拿来证明所有人工建议都应直接执行。[原摘要](https://pubmed.ncbi.nlm.nih.gov/25305591/)
- **DAPT—CD133，`27084744/r16`：** 原文讨论 DAPT 清除 CD133 阳性细胞及改变这些细胞的放射敏感性。细胞数量减少，不能直接等同于 CD133 基因表达下降。原参考为 `Association`，需要保留“细胞群”和“标志基因”粒度不同的问题。[原摘要与图示](https://pubmed.ncbi.nlm.nih.gov/27084744/)
- **p19／TRFP，`18507837/m24`、`m31`：** p19 的原文明示 `CDKN2D [p19]`，支持程序的 `1032`，而固定参考是 `1029`。TRFP 有同名对象；全文中的染色体位置和功能说明支持 MED20 `9477`，固定参考却是 USP47 `55031`。这些应登记为参考疑点，不能为了匹配旧参考把有依据的程序结果改坏。TRFP 使用了全文补充证据，也要与只用摘要的原 BioRED 评价范围区分。[原论文](https://link.springer.com/article/10.1186/bcr2100)、[CDKN2D](https://www.ncbi.nlm.nih.gov/gene/1032)、[MED20](https://www.ncbi.nlm.nih.gov/gene/9477)、[USP47](https://www.ncbi.nlm.nih.gov/gene/55031)

最后看 `19306381/r5`、`r6` 的 `invalid_judgment`。问题可能出在核查模型引用了带省略号的拼接文本，程序无法把它定位为一段连续原文。**引文定位失败不等于关系为假。** 可以同时保留 `Association` 候选、要求补充连续引文，并继续核对物种和 ID。[原摘要](https://pubmed.ncbi.nlm.nih.gov/19306381/)。

**到这里应明白：** 名称、身份、关系、证据和审阅意见是不同的检查对象。定位到具体字段，才能决定该改什么；仅看到一行被列入问题表还不够。

## 第三步：理解改动，再运行改进版

先回想第二步的几个原因，再看本次改进做了什么：

1. **完善候选和别名处理。** 候选仍来自独立外部数据库；增加覆盖、处理可解释的写法差异，让后续选择有机会找到合适对象。
2. **按提及位置检查上下文。** 利用局部物种和细胞背景重新检查链接，不把同一名称在全文所有位置自动视作同一身份。依据不足时保留不确定性。
3. **保守处理明确的局部关系句式。** 只对程序能够辨认的表达调整标签；无法确定对象或语义的情况保留待审，不把一个关键词当作整篇生物学结论。

**为什么固定旧预测：** 如果同时重新抽取名称、换模型、换提示、改词典，就很难知道结果变化来自哪里。本轮保留旧抽取，只观察这些本地处理规则带来的变化。

想看看程序实际改在哪里，可以只阅读 [链接改进模块](../src/bio_knowledge_lab/improvement.py) 和 [关系句式模块](../src/bio_knowledge_lab/relation_rules.py)：前者逐次查看提及和来源，后者识别少量明确的干预句式。你不需要自己编写代码。旧版 [上下文对齐模块](../src/bio_knowledge_lab/contextual_alignment.py) 仍保留，方便对照“同名合组”与“逐次核查”的差别。

**输入：** `baseline.jsonl`、增强的独立候选库和有来源的上下文资料。优化函数不读取评分 gold，也不读取审阅案例中的目标答案。运行入口可以随后使用 gold 计算成绩，但“生成新版预测”和“给预测评分”是分开的操作。

```bash
python -m bio_knowledge_lab feedback-lab --step optimize --workdir runs/feedback
```

打开以下两个文件：

- `runs/feedback/improved.jsonl`：本地改进规则实际运行得到的新结果。
- `runs/feedback/improved_evaluation.json`：新版按同一套固定参考计算的成绩。

在 `improved.jsonl` 中再次寻找刚才的文献和提及。先看链接是否变化，再看 `improvement_review`：`rule_candidate` 表示本地规则提供了依据，`needs_review` 表示仍需核查，`not_rechecked` 表示本轮规则没有完成这项核查。`previous_links` 保留修改前的值，`evidence` 可回到原文定位。最后看 PKCalpha 与 p21／p27 的关系和 `relation_rule_review`。不要只找“变对”的例子，也要留意没有变化的记录。

此处没有新的语言模型回答。旧版真实响应、提示和缓存保持原样；`improved.jsonl` 的变化来自本地规则，不能称作“DeepSeek 重新理解后给出的答案”。将来若改变模型提示、候选列表或检索输入后重新请求模型，必须保存相应的新真实响应，不能继续把旧回答当作新输入的推理结果。

**到这里应明白：** 改程序规则与重新调用模型是两件事。新版结果必须由实际运行产生，而不是在结果文件里直接填参考答案。

## 第四步：查看哪些改善了，哪些仍需要解释

**为什么做：** 几个讲解案例变好，不足以证明整体方法变好。增加候选、放宽名称匹配或改变规则，也可能引入新的错误，需要把改善和退步一起看。

**输入：** 旧版和新版预测、同一份固定 gold、诊断案例信息。

```bash
python -m bio_knowledge_lab feedback-lab --step compare --workdir runs/feedback
```

打开 `runs/feedback/comparison.md`。这是程序生成的比较说明，不是让你提交的表格。按下面的顺序读：

1. **先看分组。** 涉及本次反馈的 10 篇用于分析和调整；其余 40 篇作为本轮未参与调整的验证文献；全部 50 篇用于查看总体变化。此前这些材料已经用于项目开发，40 篇不能称为新的独立测试集。
2. **再看指标。** 对照两版的链接精确率、召回率和 F1，再看端到端关系指标。不能只挑提高的一项。减少随意链接可能提高精确率，却也可能降低召回率；反过来，多选一些 ID 也可能扩大覆盖但增加误连。
3. **回到具体记录。** 找出改善、未变和退步的例子，结合第二步的原因读。由于实体名称、类别和位置没有重新抽取，实体识别成绩应保持不变；不能将链接改进说成名称抽取能力提高。
4. **最后看仍待解释的项目。** 严格链接要求完整 ID 集合匹配。只找到其中一个 ID、主动保留不确定性，或者遇到原参考疑点，都可能仍被固定评分记为不匹配。这与“每一个已选 ID 都在生物学上错误”不同。

本轮实际数值、改善记录和退步记录以这次运行的 `comparison.md` 为准。**不预设每一项指标一定提高，也不把改善几条案例称为全部科学问题已经解决。** 特别是 p19、TRFP 等参考疑点，应把固定 gold 的评分与独立的原文解释并列理解，不修改参考来制造更高分数。

课程随附的 [2026-11-18 实测快照](../reports/improvement_comparison.md)可供核对：全部50篇的严格链接 F1 从61.92%变为62.17%，端到端关系 F1 从17.28%变为17.40%；实际改了5处 ID 和3处关系标签，其余40篇本轮验证文献的指标不变。提高幅度有限，仍有大量差异需要解释。这份快照不能替代你自己运行产生的结果。

**到这里应明白：** 一次可解释的改进要有同样的输入和评分规则、真实的新结果，并同时检查已分析案例和其他文献。结果没有改善或出现退步，也能帮助确定下一步该查什么。

## 体验结束后应能看懂什么

无需另外写作业。回到刚生成的文件，确认自己能顺着一条记录说清以下过程即可：

> 旧版给出了什么 → 它与参考或原文哪里不同 → 问题发生在候选、规则、模型判断还是参考解释 → 新版具体改了什么 → 哪些结果变化了 → 还有什么不能确定。

这与 [操作手册第 7 节](MANUAL.md#7-修订保留历史并加入新文献)的教学故障恢复是不同的体验：那里观察一次明确修改怎样保存历史，这里观察真实处理方法的改动是否改善预测。两部分都不会自动把所有输出升级为人工确认的生物学事实。
