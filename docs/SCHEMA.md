# 记录格式、字段依据与金标边界

一条关系记录表示：**某篇文献对一对实体给出的一个文档级关系标注或模型候选**。它不是跨所有实验条件成立的生物学定律。实体的统一标识用于连接文献；每篇文献的关系、上下文、证据和处理历史独立保存。

## 1. 文件分层

| 文件 | 内容 | 是否允许输入待测模型 |
|---|---|---|
| `data/corpus/documents.jsonl` | 原文、来源和课程初始／增量分组 | 允许 |
| `data/kb/entities.jsonl` | 从独立公开数据库取得的标准名称、别名、标识和来源 | 用于对齐；不是从待评文献金标抄出的名称表 |
| `data/reference/gold.jsonl` | 原数据集人工标注及其转换后的参考表达 | 仅评价或明确标为参考实验时读取 |
| `data/replay/` | 本项目真实 API 响应、解析结果与调用元数据 | 免费回放；不是人工金标 |
| `runs/` | 学生自己生成的候选、数据库、评价和修订历史 | 学生工作目录，不应提交凭据 |
| `data/manifest.json` | 数据版本、下载来源、哈希、选样及坐标约定 | 可读取 |

课程的 `initial`／`incremental` 是导入顺序，不等于原作者的训练／测试划分。不能把已用于提示调试的文献冒充独立测试资料；报告中应分别保留和说明两种划分。

## 2. 文献

`doc_id` 是稳定的文献主键。文献保存 `title`、`abstract`、`text` 和 `split`。本项目的坐标文本为 `title + "\n" + abstract`；转换程序负责与原始 BioRED 坐标对照。位置采用 Python 字符串的左闭右开区间 `[start, end)`，不是 UTF-8 字节位置。

所有实体与证据跨度必须满足：

```python
document["text"][start:end] == annotated_text
```

位置正确只能说明定位无误，不能证明抽取的语义正确。

## 3. 实体提及与标准实体

| 字段 | 含义 |
|---|---|
| `mention_id` | 一篇文献内的一次实体提及；同名重复出现可有不同提及编号 |
| `text`、`start`、`end` | 原文及其精确位置 |
| `type` | 所选 BioRED 版本的原生实体类型；不把论文简称静默替换成新标签 |
| `links` | 候选或已确认的标准标识列表，包含 `namespace`、`id`、`score`、`method` |
| `link_status` | 对齐状态；未解析或歧义状态必须保留 |
| `link_candidates` | 尚未作为确定关联接受的外部候选；不直接用于合并 |
| `link_review_status`、`link_evidence` | 上下文模型选择的审核状态及来源证据；`resolved` 不等于人工确认 |

原始标注覆盖基因／基因产物、疾病／表型、化学物质、序列变异、物种和细胞系六类。原始的基因类别可以包含蛋白、mRNA 等基因产物；不能仅凭该标签生成独立蛋白异构体的金标。一个组合提及也可能对应多个标识，不能只保留第一个。

本次官方 ZIP 的六种原始枚举是 `GeneOrGeneProduct`、`DiseaseOrPhenotypicFeature`、`ChemicalEntity`、`SequenceVariant`、`OrganismTaxon`、`CellLine`。内部匹配代码可以使用明确映射的简称，但导入和报告必须能追溯原值。

标准标识使用“命名空间＋标识符”共同识别。同名异物种不自动合并。`score` 是方法内部得分，不是“生物学事实正确的概率”。

## 4. 关系

抽取阶段的每条关系包含：

| 字段 | 含义与规则 |
|---|---|
| `relation_id` | 文献内关系编号；持久化时与文献编号共同构成记录身份 |
| `head`、`tail` | 指向本篇文献的 `mention_id`，必须存在；命名不等于生物学因果方向 |
| `type` | 原数据版本允许的关系类别，不擅自扩成新的因果标签 |
| `novelty` | 原研究的新发现／背景知识角色；不能当作真实／虚假标签 |
| `evidence` | 候选证据跨度列表；逐条记录原文位置 |
| `context` | 有明确文本依据的上下文，未报告的内容保留空 |

BioRED 的人工关系是文档级实体对关系，可以跨句成立。一个文献级金标不能自动拆成多条有人工保证的逐句证据。原版没有独立的关系方向金标；不能根据两个 ID 的排列顺序推断“谁作用于谁”。若未来引入 BioREDirect 的方向扩展，必须单独记录数据版本和新增标签来源。

本次 ZIP 的八种关系是 `Association`、`Positive_Correlation`、`Negative_Correlation`、`Bind`、`Cotreatment`、`Comparison`、`Drug_Interaction`、`Conversion`。原始 novelty 值为 `Novel`／`No`；模型不能判定时使用课程新增的 `Unknown`，它不属于原作者人工标注标签。

“负相关”“没有标注关系”“模型没有找到关系”“证据不足”分别存储和解释，不混用。某条关系出现在背景叙述中，也不意味着本篇实验再次证明了它。

## 5. 证据、上下文和参考状态

| 内容 | 已有公开人工参考的范围 | 本项目的处理 |
|---|---|---|
| 实体边界和类别 | BioRED 人工标注 | 严格边界／类别评价 |
| 实体标准标识 | 原数据已有标识 | 对齐结果与之比较，不能把答案预填到预测中 |
| 文档级关系及 novelty | 原数据已有标注 | 保留原值并评价 |
| 单句最小证据、全部实验条件 | 原版没有覆盖这些字段的完整金标 | 保存为候选；科学审阅前不计作人工金标 |
| 原文出处和定位 | 文献、字符跨度可自动核对 | 程序核对，语义有效性另行记录 |
| 修订操作是否生效 | 课程定义的操作与期望状态 | 用历史及查询回归验收 |

同一记录中的不同部分可以有不同参考状态：实体 ID 已有金标，证据句仍可能待核对。禁止把整条混合记录统一标成“专家确认”。

## 6. 版本和更新

更新必须保留文献身份、记录身份、修改前后内容、修改原因和依据，不能用覆盖文件的方式抹去历史。跨文献融合保留独立证据；再次导入完全相同的记录不能膨胀为重复知识。

教学故障必须明确标为课程注入，其修复目标由原始副本确定。真实模型错误则保留真实响应，不把修正后的内容冒充模型首次输出。评分参考数据不随学生修改同步改写。

## 7. 规范依据

- [BioRED 官方标注指南](https://ftp.ncbi.nlm.nih.gov/pub/lu/BioRED/BioRED_Annotation_Guideline.pdf)：实体、标识、关系和 novelty 的来源。
- [ACL 2026：Refining and Reusing Annotation Guidelines for LLM Annotation](https://aclanthology.org/2026.acl-long.1760/)：指南驱动的实体标注与严格比较；不提供完整知识库模式。
- [ACL 2026：CoRE](https://aclanthology.org/2026.acl-long.1517/)：文档级关系任务参考；未据此宣称复现其模型。
- [ACL 2025：LLMs-as-the-Judge for Biomedical Relation Extraction](https://aclanthology.org/2025.acl-long.1238/)：结构化预测与既有参考关系比较；不把模型裁判当作金标生成器。

文件布局、记录主键、处理版本、修订历史及教学故障机制为课程工程设计。
