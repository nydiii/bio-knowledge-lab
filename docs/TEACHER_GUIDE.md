# 教师说明

学生统一使用[完整操作教程](MANUAL.md)。第1—7步体验从文献到资料库的过程，第8—11步体验发现问题、改进程序和比较结果。已经完成基础流程的学生，更新项目并确认环境后，可以直接从第8步继续。

**这次是跟随操作体验，不要求交表、写报告或完成评分作业。** 教师带着学生看懂一个具体例子即可，不用让学生解释每个字段。

## 先讲清楚要做什么

实训围绕两个问题：怎样把文献整理成能查询的资料库？程序给出的结果有问题时，怎样找到原因并检查改进是否有效？

- **模型**读文字、提出名称和关系等判断；这些判断可能出错。
- **程序**读取模型回答、选择标准编号、保存资料、检查格式和计算分数。
- **学生**运行命令，打开结果，回到原文看一个例子，理解这一步解决了什么问题。

本课读取提前保存的真实模型回答，没有让模型重新作答，也不训练新模型。学生完成免费主线不需要密钥或额外付费。

## 怎样带学生走完

每一步只强调三件事：现在做什么、为什么做、结果在哪里看。术语随例子解释，不先列一长串定义。

1. 跟着教程看 IL-6：先找到名称，再看全称和缩写怎样连接到同一个标准编号。
2. 查询多篇文献，确认不同文章的来源和说法仍然保留。
3. 看一次预设错误怎样修改、怎样保留历史，再加入10篇文献，检查重复导入会不会多算。
4. 进入改进体验，先看真实旧结果和核查意见，再理解程序改了哪里，最后比较新结果。

可在课堂上请学生指着结果口头说明一句：“这里原来是什么问题，修改后发生了什么？”不明白的地方当场补讲，不另设填写任务。

一键演示、其他模型对照、付费调用和软件测试均为选做，见学生教程末尾的说明。学生完成正文即可；不要要求把所有可选命令再跑一遍。

## 看结果时要分清什么

**人工参考、核查意见和程序结果分别保留。** 数据集作者的人工参考用于计算分数；本次核查意见帮助解释具体问题；程序的新结果仍可能出错。它们不能互相替代。参考文件在 `data/reference/gold.jsonl`，整理后的核查说明在 `data/improvement/review_cases.json`。

本轮收到的24条意见覆盖22条不同记录，第11、12条仍没有人工结论。确认一个关系标签合理，不代表同时确认了两端的物种和标准编号；意见之间有疑问时继续保留待审。

基础流程的“先40篇、后10篇”是导入顺序。改进体验里的“10篇反馈案例、其余40篇”是另一种分组：涉及反馈的10篇用于分析和调整，其余40篇用于检查其他文献是否受影响。这50篇以前都已用于项目开发，其余40篇不能称作新的独立测试集。

新版固定原来的模型回答，只改候选资料和少量本地规则。改进程序不读取参考答案来生成预测；预测完成后，再按同一份参考计算分数。比较结果保存在 `runs/feedback`，不会自动写回基础流程的资料库。

**分数提高只是本次比较的结果，不是所有问题都解决了。** 要同时看改善、未变和退步；不确定的身份、证据和参考争议应继续保留。软件检查通过，也不代表每条生物学判断都正确。

需要查阅具体依据时，再打开[数据来源](DATA_SOURCES.md)、[实际验证记录](VERIFICATION.md)和[方法边界](METHODS.md)。本项目是教学适配，不是原论文全部实验与指标的复现。
